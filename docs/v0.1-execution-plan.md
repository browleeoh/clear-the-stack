# V0.1 field-guidance execution plan

**Purpose:** Durable, ordered ledger for the guarded post-V0 field-guidance correction
loop.

**Review base:** `origin/main` at `1cb4d99` (August 29, 2026).

**Authority:** The approved field-guidance review is the scope authority for this
ledger. `docs/product-spec.md`, `docs/architecture.md`, and `docs/card-data.md`
remain the product, technical, and attribution authorities. This ledger cannot add
product scope or make new product decisions.

This is a correction milestone after completed V0 work, not unfinished V0 work.

## Status and ordering rules

- `complete`: merged into `main` and verified on `origin/main`.
- `ready`: dependencies are complete and the unit may be selected.
- `queued`: approved but not selectable yet.
- `blocked`: requires an explicit user or external decision.

Only the first `ready` unit may be selected. A merged unit may promote only its
immediate ordered successor, except that FG-03 must leave FG-04 `blocked` at the
mandatory field-validation gate. FG-08 has no technical dependency, but remains last
for release coherence.

Every unit is a separate issue, fresh `codex/` branch, independent review, commit,
pull request, required-CI result, and guarded merge.

## Shared source, validation, and exclusion requirements

Before authoring any unit, recheck and record in the issue and review evidence:

1. The current Wizards Comprehensive Rules version and effective date.
2. Current HOB Oracle text against the normalized catalog.
3. The Hobbit Release Notes' continued lack of a card-specific entry for Large Bear
   and Troll Negotiations when either card is used.

Use current Wizards rules for published outcomes, existing normalized source documents,
precise locator IDs, review dates, stable Oracle UUID joins, and unchanged route slugs.
Add `no-card-specific-entry` Hobbit Release Notes locators keyed to Large Bear and Troll
Negotiations after reconfirming their absence. CR 510.1 is authoritative: never restore
obsolete combat-damage ordering or lethal-before-next-blocker teaching.

Each unit must preserve exact-title and short partial-card-name ranking, use
beginner-language search discovery and bounded verified scenarios only for its named
scope, and pass focused tests, all tests, source integrity, type checking, production
build/prerendering, `npm run check`, `git diff --check`, working-tree inspection, and
representative mobile browser journeys.

Across the whole ledger, exclude a rules engine, AI answers, database or backend,
multi-set architecture, analytics, image or audio search, unrelated card curation,
deployment, branding, and post-milestone product work. Do not introduce a reusable
dependency outside FG-01–FG-08; report it as a blocker instead.

### FG-01 — Combat decision map and timing

Scope:

- Expand the existing Combat Learn guide while preserving its route.
- Add the phase map, decision-oriented legal-action windows, attacker and blocker
  declarations, and combat-specific instant/activated-ability examples.
- Add field-language search discovery for the reviewed combat questions.

Acceptance:

- Covers all combat steps and the four main priority windows: before attackers, after
  attackers, after blockers, and between first-strike and regular-damage steps where
  applicable.
- States that attacker and blocker declarations are nonresponsive turn-based actions.
- Preserves current sources, exact card ranking, and mobile evidence.

Exclusions:

- No multiple-block or combat-damage-assignment teaching beyond the existing overview.
- No fight or keyword concepts; those belong to later units.

Required locators: `506.3`, `506.4`, `506.4b`, `508.1a`, `508.1f`, `509.1a`, `509.1h`,
and `510.1a`–`510.1e`.

### FG-02 — Multiple blocks and current combat-damage assignment

Scope:

- Add a bounded visual or scenario treatment for one attacker/blocker versus multiple
  creatures and current combat-damage assignment.

Acceptance:

- Explains that one blocker normally chooses one attacker, multiple blockers may block
  one attacker, and a blocked creature remains blocked if its blockers leave.
- Uses a controller-choice damage-distribution scenario and contains no damage-order
  terminology.
- Defers trample to FG-05.

Exclusions:

- No trample concept or excess-damage assignment.
- No unrelated evasion or keyword concepts.

Required locators: `509.1a`, `509.1h`, and `510.1a`–`510.1e`.

### FG-03 — Fight and Troll Negotiations

Scope:

- Add a reusable Fight concept and bounded Troll Negotiations guidance.

Acceptance:

- Explains that fight is noncombat damage and neither attacking nor blocking; both
  creatures deal damage simultaneously if each remains legal.
- Explains that fighting does not tap a creature and it may later attack if otherwise
  eligible.
- Covers that Troll Negotiations puts counters on the chosen creature before the fight
  and records its `no-card-specific-entry` Release Notes locator.

Exclusions:

- No broader card curation, combat-keyword teaching, or unrelated fight applications.

Required locators: `701.14`, `120.1`, `120.2`, `120.3`, `120.6`, and a
Troll-Negotiations `no-card-specific-entry` locator keyed to its Oracle UUID.
